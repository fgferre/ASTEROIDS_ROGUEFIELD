# Source map

Read this before touching code. Each row points a subject to the file to open first, the few files it leans on, and where its tests live.

## How to use this map

- Search first: grep for the symbol, the event name (`emit('name'`, `registerEventListener('name'`) or the import path, then open what it hits.
- Open slices, never a big file whole. ESLint caps every file (`max-lines` in `eslint.config.js`), and each facade (`CombatSystem`, `UISystem`, `EffectsSystem`, `EnemySystem`, `PlayerSystem`...) hands its subjects to a folder of the same name: open the folder's module for the subject, `grep -n` the facade only for the wiring.
- Start from the Entry column and expand only along Depends on. Follow other imports only when the trail leads there.
- Content (one file per enemy, weapon, card, hull, stage, biome, boss) lives under `src/content/`; other data (tables, tuning, catalogs) under `src/data/`; behaviour under `src/modules/` (systems) and `src/services/` (session and saved state). `src/core/` is shared infrastructure, `src/utils/` small helpers.
- Services are named in the manifest (`'player'`, `'enemies'`, `'renderer'`...): grep the name in `src/bootstrap/serviceManifest.js` to find its class and declared dependencies.

## Conventions

- One way to resolve a service: declare it in the manifest entry's dependencies, then read it with `resolveService` (optional) or `requireService` (required, throws when missing) from `src/core/serviceUtils.js`. Systems extending `src/core/BaseSystem.js` cache through `resolveCachedServices`/`getCachedService`, which call the same helper. Do not add another resolver.
- Dev mode is one switch: `IS_DEV` from `src/core/env.js`.
- Data files hold tables and tuning only, frozen at export (`deepFreeze` from `src/utils/deepFreeze.js`); systems read them and own the behaviour. A new enemy, weapon, card, hull, stage, biome or boss starts as one file under `src/content/<kind>/`, not as an edit to the engine.
- A content file imports only constants (`src/data/constants/`), `src/utils/deepFreeze.js`, `src/data/layerParts.js` and other content files, never `GameConstants` nor a module that reads the registry: that is an import cycle and the game fails to load.
- A refactor must leave play unchanged, and `tests/integration/golden-trace.test.js` is the proof: it plays fixed headless runs and compares per-second hashes of state and events with `tests/__fixtures__/golden-trace.json`. Regenerate the fixture only in a commit that means to change behavior (command in the test's header: `GOLDEN_UPDATE=1 npx vitest run tests/integration/golden-trace.test.js`).
- Generated artifacts are not source: `npm run analyze:deps` writes the dependency graph under `docs/architecture/`, which is git-ignored. Regenerate it; never edit it or treat an old copy as current.
